Exercises

Each exercise below runs one task more than once and changes a single thing about how the agent is run. What you are measuring is never the subject of the task. It is what changed when you changed the setup, and whether you could tell. Most of them ask you to use a piece of your own work, because an answer you can judge is worth more than one you cannot. One word used below. A TURN is one step of the loop: the agent acts, sees what came back, and decides what to do next. Counting turns is the cheapest measure of how much work a run actually did.

What you ask for changes what you get

first turns up on day 1

The instruction you type is not just a description of the task. It also decides what the agent produces, what it checks, and what it hands back. A request can be bare - "do this" - or it can say, before any work starts, which files you want at the end, in what format, and what the result has to satisfy before the agent considers itself finished. The second kind takes a few minutes to write and is the single cheapest change available. In this exercise you ask for the same thing both ways and see what the difference is worth.

what changes between runsHow much the request specifies before the work starts.
what to do

Pick a task from your own work. Ask for it once in a sentence. Then ask again, in a new directory, with a request that names the files you want, their format, and the checks the answer has to pass.

what to compare

What each one left behind. Whether the bare version checked anything you had not asked for. Then look at the list of things you had to spell out the second time, and decide which of them you would rather say once, in a file, than repeat every time you start.

what you are given

Nothing. Your own project.

The model, and how hard it thinks

first turns up on day 1

These tools give you two dials. The first is which MODEL runs - the underlying system, of which each provider offers several, at different prices and speeds. The second is REASONING EFFORT: how much thinking the model spends before it answers. It is a setting, usually with names like low and high, and it is independent of which model you chose. Most people set neither and never learn what either is worth on their own work. In this exercise you turn both and watch what moves.

what changes between runsWhich model runs, and how much thinking it is told to spend.
what to do

One task from your own work, run four times: two models, each at a low and a high effort setting. Same request every time, written down before you start so it does not drift between runs.

what to compare

Not only whether the answers agree. Whether the CHECKING agrees - what each run verified on its own initiative, and what it quietly stopped doing when the dial went down.

what you are given

Nothing. Your own project.

what happened when we ran it

On day 2's grid, turning the effort down did two different things to two models. One returned a different number and kept verifying it. The other returned the identical number to four figures and stopped verifying altogether, which is the more dangerous of the two failures because nothing about the output says so.

Getting an agent to use a project's notes

first turns up on day 1

A project can keep its own notes: what has been decided, what has been derived, what was got wrong and later corrected. Kept as ordinary files in the project - a set of them is usually called a wiki - they are the only record that survives a session ending. They are worth nothing if the agent does not read them, and it will not open a directory it has no reason to open. Two things can give it that reason. A CLAUDE.md is a file the tool reads at the start of every session in that directory: it always applies, and it costs some of the session's limited attention whether or not the question needed it. A SKILL is a set of instructions the agent loads only when it judges that what it is doing matches the skill's description: it costs nothing until it fires, and it can be installed once for every project you have - but it can also fail to fire. In this exercise you ask one question in four directories and find out whether the notes are opened at all, and whether the answer changes when they are.

what changes between runsHow the agent comes to read a project's notes, or whether it does at all.
what to do

One question, four directories. a/ empty. b/ the notes and nothing else. c/ the notes and a CLAUDE.md that mentions them. d/ the notes and a skill that says to read them. The same question in all four.

what to compare

Whether b opens the notes at all - that is the one to watch. Whether the answer changes. Whether a run can tell you which page it used.

what you are given

day5/exercise-notes/ - the question, the CLAUDE.md, the skill in both layouts, and a real project wiki: 105 pages behind a published paper, with an index, a notation contract, a formula list, fifteen concept pages, a page per source read and an append-only log.

run it on

The question that ships with it. Better, once you have done it once: build notes for a project of your own with the build-project-wiki skill in day5/skills/, and ask something whose answer you already know.

what happened when we ran it

a and b gave the same wrong answer and neither opened anything. b began its reply by saying it would work the problem out directly rather than reach for a skill, with the notes sitting in the directory beside it. c and d read the notes and returned a result that is written down there and in no publication. The skill in d fired unprompted, on a description that names no subject matter and no filename.

The same task twice, changing nothing

first turns up on day 2

Ask the identical question twice - same model, same settings, same words - and the two answers will not be identical. How far apart they are is your noise floor. This matters for every other comparison you will make. If you change a setting and the answer moves by less than the noise floor, you have learned nothing, and you cannot know that until you have measured it. Nothing else in this course runs the same thing twice unchanged, so nobody yet knows what this number is.

what changes between runsNothing. That is the point.
what to do

Take a task from your own work and run it twice, in two directories, with the same model, the same settings and the same words. Then a third time if the first two disagree in a way you did not expect.

what to compare

The two answers. Then the harder question: if somebody had told you these two runs differed in their setup, which difference would you have believed was responsible?

what you are given

Nothing. Your own project.

what happened when we ran it

While testing another exercise on this page we ran two directories whose only difference was a folder that neither agent opened. They gave different answers - one right and one wrong. That is what an unmeasured noise floor looks like when it is mistaken for a result.

Leaving it to run without you

first turns up on day 2

You can use these tools as a conversation, answering questions as they come. You can also start one with a single command that runs to completion with nobody watching and hands back whatever files it produced. That second mode is called running HEADLESS, and it is how you use an agent for anything that takes longer than you are willing to sit for. It also removes the thing you were relying on without noticing: you. In this exercise you run one task both ways and compare what came back.

what changes between runsWhether you are there while it works.
what to do

A task from your own work, run once as a conversation and once as a single command with no interaction. Give both the same request.

what to compare

The files each one left. Not the summary it wrote about itself - the files. A run that describes what it did is not evidence that it did it.

what you are given

Nothing. Your own project.

what happened when we ran it

One run in day 2's grid reported success, exited cleanly, took 109 turns, and produced no output file at all. Nothing in its own summary said so.

A second opinion from a session that knows nothing

first turns up on day 3

An agent that has been working on a problem with you has your context and your assumptions, and has spent the whole session building the thing you are now asking it to criticise. A session started fresh, given only the output, has none of that. In this exercise you get both opinions and compare them.

what changes between runsWhether the reviewer has any of the history.
what to do

Take something your agent produced. First write down yourself what you think is wrong or weak in it. Then open a new session, give it the output and nothing else - no transcript, no reasoning, no context - and ask what is wrong with it.

what to compare

Your list against its list. What it found that you had not. What it objected to that turns out to be fine, and whether you can tell which is which without going and checking.

what you are given

Nothing. Your own project.

Skills and hooks

first turns up on day 5

A skill, defined above, is loaded by the agent when it judges that the task matches - which means it can also go unloaded, and nothing announces that it did. A HOOK does not depend on that judgement. It is a command the tool runs at a fixed moment whether or not the agent thinks of it; the one used here runs at the moment the agent decides it has finished, and if that command reports a problem the agent is not finished after all - the message comes back as a new turn and it keeps working. Both are ways of getting the same rule obeyed, and they fail differently. A skill can go unloaded; a hook cannot make an agent do something it does not already know how to do. In this exercise you run one task in three directories that differ only in which of the two is present.

what changes between runsWhether the rule is written down, and whether anything enforces it.
what to do

One task, three directories, the same request and the same model in each. a/ is empty. b/ has a skill stating the rule and a hook that checks it. c/ has the hook and no skill. Then read the three directories side by side - the directories, not the replies.

what to compare

Where the result ends up: in a file, or only in a message on screen that disappears when you close the terminal. Whether the hook ever has to fire. What the difference cost in turns.

what you are given

day5/exercise/ - the request, the skill, the hook, the rule it enforces, and the wiring for both command-line tools.

run it on

A short calculation ships with it, which needs no data and takes seconds. Any task that produces a figure and a number will do, including one of your own.

what happened when we ran it

a left its result in the reply and nowhere else. b wrote the record without being asked, and the hook never had to fire. c decided it had finished, was stopped by the hook, and complied. All three got the same answer, and the record cost nothing in turns.

The same content in two output formats

first turns up on day 5

This course is delivered in two formats. The lectures are SLIDEV decks: a file of markdown, built into a PDF by a script. The sessions are single self-contained HTML pages, generated by a different script from a file of prose plus whatever the runs produced. Both ship here with the source they were built from, so you can see how each is made. An agent will produce either on request, and does different things for each without being told to. In this exercise you have it build the same content both ways and decide which one you would keep up to date.

what changes between runsThe output format, for something you would have to maintain yourself.
what to do

Take something of your own - a result, a paper, a talk you owe somebody - and have an agent build it as a slidev deck, and then as a self-contained page. Same content, twice.

what to compare

Which one you would be willing to maintain, and why. What each format makes easy and what it makes impossible. What the agent did differently for each without being asked.

what you are given

Both sources ship. Every lecture-*/ carries the slides.md it was built from, its figures and its build script; how-a-page-is-built/ carries the page builder, its template, and one session page's source.

run it on

Yours. This is the one where using somebody else's subject defeats the point.
