The final project

Take a problem of your own and do the whole of it the way this week has been doing things: with an agent, with the provenance written down as you go, and with enough evidence at the end that you would defend the result to somebody who did not watch you produce it.

One word, before it is used below. The PROVENANCE of a result is the record of where it came from - which file and which function produced it, what went in, what was written from scratch against what was called out of a library, and every choice that had a defensible alternative. It is the difference between a number you can hand to somebody and a number you can only assert.

Choosing the problem

Pick something from your own research, or a gravitational-wave problem based on what the week covered. Either is fine and the first is usually better, because you can tell whether the answer is right.

It is worth choosing one with many components - an analytic derivation, code, figures, data. The week has five hours in it and each one varies something different about how a task is run: what you ask for, which model and how hard it thinks, whether you are there while it works, how many agents are on it, and what is sitting in the directory before any of them starts. A problem with only one part gives most of that nowhere to be used. A problem with four parts gives all of it somewhere.

Doing the work

Have the agent do the calculations and the figures, and have it document the provenance of every one of them as it goes, along with how each result was checked. Both halves matter and the second is the one that gets skipped: a figure with a recorded origin and no check behind it is still only an assertion with a picture beside it.

You can have a second agent check the work independently - a session started fresh, given the output and none of the history, which is the exercise on the exercises page in its full-size form.

Ultimately you are responsible for it being correct, exactly as you would be in any other piece of work. So produce enough artefacts that you are actually confident: not enough to look thorough, enough that you would stand behind the result. That judgement is yours and there is no rule for it, which is the point.

What you hand over

Everything goes in a GitHub repository. Inside it, two things you present from - an HTML page and a PDF - and the rest of the repository behind them.

The split is deliberate. The page and the PDF are for people: they are what you put on a screen and what somebody reads on paper. The repository is for machines. Anyone who clones it should be able to reproduce all of it with an agent, which means the instructions, the environment, the data and the checks are in there and are readable by something that has never spoken to you.

That is the test the whole week has been building towards, and it is worth applying to your own repository before you hand it over: hand it to a fresh agent that knows nothing, ask it to reproduce a result, and see how far it gets.
